# 功能方向与候选

更新：2026-10-18。画面明亮面积检测与夜间暂停模板已交付本机，配合已有亮度恢复动作，HDR/时段外停采；实际成本与未测项见 [验收记录](../exec-plans/completed/screen-content-brightness.md)。下一批候选未确认不启动。

## 产品方向

实用Windows自动化工具：用户配置“何时、做什么”，真实执行、结果可解释、能暂停、UI退出仍工作。HDR只是首个场景。四阶段（自动化→用户主动开启的本地观察→可审阅建议/离线辅助→用户确认的源码扩展）已有闭环，后续按真实需求增加能力，不重做地基。

规则编辑与工具箱并列：固定场景提供选对象、选模式、启用的直接入口，避免为了简单操作拼规则。托盘管理提供仅Axiom启动时隐藏/系统事件持续隐藏两种模式；持续不轮询。未来工具逐个按需求增加，不提前铺工具框架。

2026-10-21本轮增加“定时Hosts”：按现有检测更新多个域名的系统hosts管理记录，自定义DNS、DoH及bootstrap；日历检测增加每月多日期和月末，既有间隔/每日每周/单次/时段模式继续复用。它是已授权的具体工具，不扩展任意系统文件编辑或脚本执行能力。

## 候选，确认后才启动

| 候选 | 最小范围与未决边界 |
|---|---|
| 少量窗口工作布局保存/恢复 | 先限定明确窗口；处理缺屏、DPI、多实例及应用拒绝，不扩成整桌面恢复系统 |
| 指定耳机/音箱音量 | 本地输出设备选择及失效处理；设备标识只留本机，不先改默认设备或建通用设备平台 |
| 显示器硬件电源控制 | Power Display提示有可行接口；重新唤醒、支持性和权限仍需单独确认，不能混同现有系统关屏请求 |
| 其他场景 | 旧候选完整保留在 [历史目标](../history/roadmap-through-20261016.md)，只按本轮收益/API/验收条件选取，不自动恢复旧队列 |

已有指定应用音量、Wi-Fi、USB实例、窗口移屏与条件恢复等能力，选题前核对实现；持久显示器身份、USB容器/型号与具体音频设备选择不能冒充已实现。

## 交付约束

每轮只交付用户明确结果及必要直接边界，复用通用声明/编辑/Engine；配置→检测→动作→解释→暂停完整可用。默认一个实现代理、限定验证、相关结果复用、及时commit/push；合并和Release按有意义功能批次，文档轮不发版。规则见AGENTS和 [工作流](../development/workflow.md)。
